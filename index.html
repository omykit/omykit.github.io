How Jarvis decides

My main project routes every request before it reaches a model. Known commands, like opening an app or asking the time in another city, run directly. Open-ended questions go to a local Qwen model through Ollama, and its answers pass a guardrail that blocks made-up times and dates.

Selected work

J.A.R.V.I.S 2.0, a microservice AI voice assistant

  • Python
  • FastAPI
  • Docker Compose
  • Ollama
  • Neon PostgreSQL
  • pytest
  • Rebuilt my desktop voice assistant as four FastAPI services (Gateway, Command, AI, Memory) on Docker Compose, so each part can be tested and restarted on its own.
  • The gateway routes each request: known commands run deterministically, and open-ended questions go to a custom Qwen 2.5 model served locally through Ollama.
  • Conversation memory lives in Neon PostgreSQL over verified TLS and is fed back into prompts, with a migration script to move the old JSON memory across.
  • An output guardrail stops the model stating a current time or date it can't know, after a real session caught it inventing one.
